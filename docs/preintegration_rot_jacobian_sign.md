# 预积分旋转雅可比的四元数符号

## 问题

`PreintegrationNormal::evaluate` 的姿态残差由旋转矩阵 `M_rot` 恢复四元数 `q_rot` 后取
`2 * vec(q_rot)`；旋转行的解析雅可比则按状态四元数乘积
`q_prod = corrected_q^-1 * q0^-1 * q1` 推导。`q` 与 `-q` 表示同一姿态：

- 残差只依赖旋转矩阵，与状态四元数的符号无关；
- 当 `q_prod` 与 `q_rot` 符号相反时，解析雅可比的旋转行与残差差一个负号。

每次求解后 `consistencyCheck` 会用旋转矩阵恢复四元数并重写窗口状态，符号只由 Eigen 的
矩阵转四元数分支决定。偏航相对初始化方向转到约 −93°～−157°（`w` 翻负）时，窗口里会
出现相邻关键帧的四元数符号断裂。含断裂的窗口里 LM 反复拒步、信赖域缩小到约 1e-5、
`g_last` 很大，求解“冻住”，之后一次性大跳，表现为速度跑飞和倾斜误差。

## 修复

`evaluate` 末尾计算 `rot_sign_ = sign(q_prod · q_rot)`，`residualJacobianPose0 / Pose1 /
Mix0` 的旋转行 `jaco.block(6, 3, 3, 3)` 乘以 `rot_sign_`（`Mix1` 没有旋转行）。残差不变，
也没有配置开关。修复只让雅可比与残差一致，不改变状态本身的符号；日志里的
`qsign_mismatch` 仍会出现，那是状态四元数的原始不一致，不再影响求解。

## 验证

- 单测 `test_preintegration_rot_sign`：对真实的 `PreintegrationNormal` 做中心差分，符号一致、
  符号相反两种情形下 Pose0 / Pose1 / Mix0 / Mix1 的解析雅可比都与数值差分一致（<1e-4），
  残差与状态四元数符号无关。该测试需在支持的容器/板端编译运行。
- 板端（`gyr_scale_std=0.005`，同一二进制，修复关/开各 1 次，整条序列打开 `keyframe_diag`）：

| 序列 | 含符号不一致的关键帧 | 失败步≥3 的关键帧（关→开） | `g_last` 最大（关→开） | ATE m（关→开） |
|---|---|---|---|---|
| room1 | 约 95 | 104 → 26 | 13400 → 21.9 | 0.180 → 0.087 |
| room3 | 约 108 | 124 → 13 | 8550 → 15.5 | 0.205 → 0.150 |
| room5 | 约 146 | 154 → 20 | 14100 → 41.3 | 0.165 → 0.060 |

- outdoors3 末段（第 815～845 s，动捕房、陀螺 170～200°/s）：速度误差峰值
  3～9 m/s → 0.74 m/s，最大位移速度 7～22 m/s → 2.3 m/s，路程比 1.1～1.4 → 1.01。
- outdoors5、corridor1、magistrale1：均不发散。magistrale1 单次 ATE 5.44（开）/ 2.76（关），
  分叉起点早于首次符号断裂，且同配置重复运行本身波动大，未归因于该修复。

以上均为单次运行；差距最可靠的指标是求解停滞关键帧数和 `g_last`，其次是 ATE。
